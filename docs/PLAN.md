## 목적과 첫 화면

학교 건축 연구자가 학교급·지역·기간으로 설계 사례를 찾고, 출처를 확인하며 변화와 노후 건물 후보를 비교할 수 있게 한다. 초·중·고를 우선하고 통합학교는 별도 범주로 둔다.

화면은 전체 동향·설계 사례·설계 사무소·건물 연령·설계 주제·연도별 분석으로 나눈다. 필터를 바꾸면 관련 표·그래프·내보내기에 같은 조건을 적용한다. 조회 기준일, 자료 기준일, 집계 기준, 포함 건수, 미확인 건수를 함께 표시한다. 연도별 분석과 사례 상세에서는 같은 조건의 키워드 근거를 가상 공간 모델에 연결한다.

## 현재 자료와 구현 범위

- 기본 자료: 경기 작품집 2023·2024·2025 당선작 166건(42·69·55건). 수작업·AI 보조 입력이며 사람의 원문 검수 전이다. 가상 예시와 별도로 선택한다.
- 조회: `award_year`를 작품집 수록연도로 취급한다. 실제 당선일·준공일이 없으므로 날짜로 채우지 않고 수록연도별 건수로 보여 준다. 기존 날짜별 조회도 유지한다.
- 상세·내보내기: 면적·층수·구조·외장·설계자·심사평 요지와 확인·검수 메모를 보존한다. 현재 메모가 있는 84개 사업·중복 제거한 208개 메모를 전체 또는 선택 조건에서 계산한다. 이것이 수치 오류 84건이라는 뜻은 아니다.
- 결측: 2024년 주제 근거·사무소 ID 연결은 아직 없고, 2023년 출처 URL도 미확인이다. 학교·건물 기본정보가 없어 실제 학교 수·건물 연령을 만들지 않는다. 2024년 주제 미수록을 0% 발생률로 해석하거나 전년 대비 감소로 계산하지 않는다.
- 공간 비교: 외부학습·지역공유·가변학습 키워드를 같은 가상 학교의 3D 개념도에 표시한다. 회전·확대·지붕/앞벽 숨기기와 SVG 저장을 제공하며 출처·이용 조건·가정을 함께 남긴다. 실제 학교 재현·IFC 변환·자동 모델 생성 학습은 구현하지 않았다.
- 운영: GitHub Pages 정적 배포를 사용한다. 브라우저 안에서 JSON을 읽고 필터·다운로드를 처리하며 도구 내부 AI 호출은 없다. 자동 수집·갱신 예약·Qwen TTS 설명영상은 아직 없다.

## 1차 개발과 확장

현재는 수동 입력한 Snapshot JSON과 가상 예시를 HTML/CSS/JavaScript 정적 모듈로 보여 준다. 실제 자료의 입력 검증 통과와 사람의 원문 검수 완료는 구분한다. 프레임워크와 자동 수집은 필요·범위 합의 후 추가한다.

```text
CSV/JSON 입력 또는 검토된 공개 자료
  → 입력 검증·정규화(A)
  → 통일된 Snapshot과 집계 함수(A)
  → 검색·표·그래프·사례 화면(B)
  → 필터가 적용된 CSV/Markdown 내보내기(A: 내용, B: 버튼·상태)
```

주제·지역·학교급 분류는 `rules/`와 공통 집계 모듈에서 관리한다. 화면 코드에 집계 기준을 중복해서 적지 않는다. 입력 객체는 `DATA_CONTRACT.md` v0.2를 따르며 v0.1도 지원한다. 작품집 확장 필드는 실제 값과 검수 메모를 유지하고 계산으로 모순을 숨기지 않는다.

자동화 확장에서는 검증된 API/RSS/내려받기 자료를 로컬 또는 CI 수집 작업으로 가져와 검사하고, 검토된 공개용 JSON만 웹페이지에 제공한다. 브라우저에서 여러 외부 사이트를 직접 크롤링하는 방식에 의존하지 않는다. API 키는 브라우저·정적 JSON에 포함하지 않는다.

`index.html`, 모듈 연결 코드, 패키지 설정과 배포 설정은 통합 담당을 합의하고 순서대로 수정한다. 위 A1·A2·B1·B2는 초기 단계의 분담 기록이다. 현재는 실제 자료와 가상 자료를 같은 공급자로 검증하며, 필터와 내보내기의 사업 식별자가 일치하는지 비교한다.

각 PR은 작업 브랜치에서 만들고 작성자 외 팀원이 실행·검산·리뷰한다. 권한 있는 담당자가 검토 후 병합하며, 에이전트 검증을 팀원의 직접 승인으로 기록하지 않는다. 같은 파일의 충돌은 변경 의도를 대조한 뒤 해결하며 수치가 맞는지도 다시 확인한다. main 직접 푸시는 최초 협업 문서 등록 이후 지양한다. 승인 1명 요구 등 보호 규칙 설정은 팀 합의 후 적용한다.

브랜치는 `<name>/YYYY-MM-DD-topic`으로 이름 짓는다. 앞에는 작업자 이름, 날짜에는 한국시간의 작업 시작일을 적는다. 한 기능은 같은 브랜치에서 이어서 작업하므로 매일 새 브랜치를 만들 필요는 없다. 2026-10-19의 통합 작업 브랜치는 `yunze/2026-10-19-issue-integration`이며, 이후 작업은 최신 main에서 해당 이슈의 브랜치를 만든다.

## 다음 개발 순서

1. 작품집 수치·학교급·쪽수·심사평 귀속을 사람이 확인하고 검수 기록을 남긴다. 2024년 주제 분류와 사무소 ID 연결, 2023년 원문 URL을 보완한다.
2. 공개·재사용 권한이 확인된 실제 이미지와 치수 도면·IFC를 확보한다. 실제 형상을 만들 때 확인된 값과 추정한 부분을 모델마다 기록한다.
3. 다른 지역·잡지·공모·뉴스로 자료를 확장하고 출처별 포함 범위와 중복 기준을 점검한다. 접근 조건이 확인된 API/RSS 등을 대상으로 자동 입력을 설계한다.
4. 충분한 근거와 검토자가 있을 때 경향 해설·전망을 작성한다. 현재 전망 틀이나 가상 모델을 실제 예측 결과로 제시하지 않는다.
5. 학교·건물 기본정보가 확보되면 아래 월별 갱신을 구현한다. 영어 내레이션과 영문·한국어 자막을 갖춘 Qwen TTS 설명영상은 실제 화면 흐름 확정 후 별도 제작한다.

## 매월 노후 건물 갱신 설계

1. 지정 출처의 자료 갱신 여부를 월 1회 확인한다. 첫 실행 시각과 담당은 자동화 구현 때 정한다.
2. 동 단위 식별자와 준공일 근거를 보존하고 폐교·철거·개축 상태를 확인한다.
3. 기준일에 40년 이상인 건물, 새로 진입한 건물, 철거 등으로 제외된 건물을 구분한다. 조회 실패·누락은 삭제나 철거로 처리하지 않는다.
4. 이전 스냅샷과 건수·필드 차이를 검사하고 검토 후 공개본을 교체한다.
5. 마지막 확인일과 원자료 기준일을 따로 표시한다. 원자료가 연간이면 월별 실행을 해도 월별 최신 자료라고 표시하지 않는다.

## 첫 검증용 사례

- 같은 설계사업을 잡지와 뉴스가 각각 다룬 경우.
- 같은 학교의 별도 증축사업 두 건, 초중 통합학교, 지역 미확인 자료.

- 준공연도만 알려져 판정이 확정되지 않는 경계 연도, 철거 상태, 갱신 실패.
- 태그 두 개가 붙은 사례, 미분류 사례, 표본이 없는 달.

## 향후 전망의 표시

첫 판은 주제 빈도와 구성 변화, 대표 사례를 보여준다. 미래 동향은 근거와 가정을 명시한 해석/전망으로 구분한다. 3년의 기사 표본만으로 전국 설계시장의 전망이나 당선 가능성을 수치 예측했다고 주장하지 않는다. 정량 예측은 일관된 시계열과 별도 평가 자료를 확보한 뒤 검토한다.
