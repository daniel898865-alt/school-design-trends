# School Design Trends · 학교 설계 동향

잡지·설계공모·뉴스의 학교 설계 사례를 모아, 최근 3년의 변화와 지역별 분포를 근거와 함께 살펴보는 웹 도구입니다.

**현재 상태: 협업 준비 및 설계 단계입니다. 실행 가능한 사이트, 자동 수집기, 실제 전국 데이터는 아직 구현하지 않았습니다.**

## 만들려는 기능

| 기능 | 표시할 내용 | 기준 |
|---|---|---|
| 최근 3년 추세 | 월별·연도별 사례 수와 설계 주제 변화 | 기준일 직전 36개월, 사용한 날짜 종류 표시 |
| 텍스트·이미지 사례 | 직접 작성한 요약, 원문 링크, 이미지와 설명 | 출처·제작자·이용 조건을 기록; 이미지 사용권 미확인은 원문 링크로 대체 |
| 시도·초중고 집계 | 지역·학교급별 설계사업 수와 자료 수 | 기사 중복을 제거한 사업 수와 기사 수를 구분 |
| 당선 사무소 | 사무소명, 공동 당선, 공개된 사업자등록번호, 확인 근거 | 당선 발표와 계약 낙찰을 구분; 확인하지 못한 번호는 비워 둠 |
| 설계 트렌드 | 주제별 비율, 대표 사례, 변화에 대한 해석 | 관측된 경향과 향후 전망을 구분; 수집 편향과 표본 수 표시 |
| 40년 이상 건물 | 학교·건물명, 준공일, 연령, 근거, 월별 변화 | 개교일이 아닌 건물별 준공일; 월별 재확인과 원자료 갱신일 구분 |

## 개발 순서

1. [기획·업무 분담](docs/PLAN.md)과 [데이터 규격](docs/DATA_CONTRACT.md)을 합의합니다.
2. 공개 가능한 사례 10~20건과 건물 예시를 준비합니다. 검증용 가상 자료는 가상임을 표시합니다.
3. CSV/JSON 입력 → 정제 → 검색·지역 집계 → CSV 내보내기가 연결되는 첫 판을 만듭니다.
4. 각자 첫 PR을 작성하고 상대가 다른 입력으로 실행한 뒤 리뷰·병합합니다.
5. 사무소·설계 주제·노후 건물 기능을 두 번째 PR로 나누어 추가합니다.
6. 검증한 정적 웹페이지를 GitHub Pages에 배포하고, 설명영상과 확인한 한계를 남깁니다.

수업용 첫 판은 **서버와 도구 내부 AI 호출 없이 작동**하도록 설계합니다. AI는 개발을 돕는 도구로 사용합니다. 월별 자동 수집은 출처·필드·접근 조건이 확인된 뒤 별도 단계로 구현합니다. 현재 예약 작업은 설정하지 않았습니다.
